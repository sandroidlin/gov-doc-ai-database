# 米花市教育局AI公文資料庫

一個單一 HTML 檔案、雙擊即可開啟的公文資料庫 PoC。把公文 PDF 拖進來，會自動 OCR 辨識並擷取發文者、受文者、字號、日期、主旨等欄位，整理成一份公文清單。找公文有兩種方式，可以隨時切換：

- **人工篩選**：用關鍵字、發文者、收文者、日期區間精準篩選。
- **AI 搜尋**：用一句話描述要找的公文（例如「今年跟課後照顧班有關的收文」），Claude 會整理重點、推薦相關關鍵字，並列出相關的公文與原因。

> 範例資料裡的「米花市政府教育局」是虛構機關名稱（借用《名偵探柯南》裡的虛構城市），僅作為示範與測試之用，與任何真實機關無關。

## ⚠️ 這只是一個 PoC（概念驗證）

- **OCR 規則是照範例假資料調校的。** 前處理與欄位擷取規則（`extractMetadata`、`parseFields` 等）都是依這批假資料的版面和用字寫的。換成**真實**的公文，版面、掃描品質、機關慣用語都可能不同，辨識效果可能不如預期，甚至抓不到欄位。
- **AI 搜尋會把公文摘要傳送到 Anthropic。** OCR 與資料儲存都在本機瀏覽器完成，但使用 AI 搜尋時，每次提問都會把公文摘要送到 Anthropic API（詳見下方「AI 搜尋的設定與費用」）。用在真實公文前，請先確認所屬單位對資料外傳的規定。
- 這個專案的目的是驗證「OCR 建檔＋AI 語意搜尋」這個做法可不可行，不是可以直接套用到任何機關的成品。

## 功能

### 匯入與辨識

- 拖曳或選擇多個公文 PDF，一次匯入、依序自動 OCR（PDF.js 渲染成圖片 → Tesseract.js 辨識，繁體中文＋英文）。
- 自動擷取欄位：**文別**（令／呈／咨／函／公告／簽／書函／開會通知單／其他公文）、發文者、受文者、發文字號、發文日期、速別、密等、解密條件、附件、主旨、說明、擬辦。
- 依發文字號與機關全銜，自動判斷每份公文是**發文**、**收文**、**局內**（內部簽呈）還是未分類，並用色塊標示。
- 相同檔名的檔案會被擋掉，不會重複匯入。

### 找公文的兩種方式

畫面上方的切換開關可以在「人工篩選」與「AI 搜尋」之間切換。切換時只會換掉搜尋區塊，下方是同一份公文清單。

**人工篩選**

- 關鍵字即時搜尋（檔名、字號、主旨、全文內容）。
- 依發文者、收文者複選篩選，以及日期區間篩選（西元曆）。
- 清單上方會列出目前套用中的篩選條件與符合筆數。

**AI 搜尋**

- **用對話的方式找公文**：直接輸入問題，或點「可以試著問問」裡的範例問題。可以接著追問（例如先問「國教科的簽」，再問「那跟廁所有關的呢」），AI 會沿用前面的條件。
- **總結**：每次回答會用幾句話整理找到幾份公文、有什麼共同點、時間範圍，以及最值得先看的是哪幾份。
- **推薦關鍵字**：點關鍵字會當成追問送出；點旁邊的放大鏡，會帶到人工篩選用原文比對再查一次。
- **AI 的理解**：清單上方會列出 AI 從問題解讀出的條件（收發方向、文別、發文者、日期區間、主題），方便確認 AI 有沒有誤解。日期與發文者可以一鍵「套用到人工篩選」。
- **相關公文清單**：依相關度排序，每筆標示「高度相關／部分相關」，並附一句相關原因。
- **在本機再核對一次**：不存在的公文、清單裡沒有的機關、格式錯誤的日期都會被拿掉，日期與收發方向也會用程式再檢查，AI 就算判斷錯也不會列出明顯不符的公文。
- **沒有 API 金鑰也能試**：還沒設定金鑰時，會改用本機規則模擬的「示範回覆」，不需要網路，也不會傳送任何資料。

### 瀏覽與校正

- 日期欄位可點擊切換「近到遠／遠到近」排序。
- 每筆公文可以打開詳細內容視窗：左邊預覽原始 PDF，右邊顯示擷取到的欄位與 OCR 全文。
- 可切到「校正內容」逐欄修正 OCR 誤判的文字；手動校正過的公文會被標記，之後更新擷取規則時不會被覆蓋。

### 批次操作

- 表格每列可勾選，表頭有全選／取消全選。人工篩選與 AI 搜尋的結果都可以勾選。
- 勾選後可批次刪除，或批次下載 Markdown（單筆直接下載 `.md`；多筆會用 JSZip 打包成 `.zip`，一份公文一個檔案）。

### 介面

- 深色介面，往下捲動時標題列會自動縮小。
- 單一 HTML 檔案、零安裝：不需要 Node.js、不需要建置流程，複製檔案給任何人，雙擊開啟即可使用。

## 使用方式

1. 下載 `AI公文資料庫POC.html`。
2. 用瀏覽器開啟。**第一次使用需要網路**，用來從 CDN 載入 PDF.js、Tesseract.js、JSZip 與中文 OCR 語言模型。
3. 按「匯入公文資料」，把公文 PDF 拖進去或點擊選擇檔案，等待 OCR 辨識完成。
4. 用「人工篩選」或「AI 搜尋」找公文。要使用 Claude，請在 AI 搜尋模式按右上角的「AI 設定」，貼上 API 金鑰。

### 想先玩玩看再說？

`米花市公文範例/` 資料夾裡有 50 份虛構的示範公文 PDF（涵蓋函、簽、書函、開會通知單等不同文別），直接拖進工具就能體驗。AI 搜尋的範例問題也是照這批公文設計的。

## AI 搜尋的設定與費用

### API 金鑰

- 到 [Anthropic Console](https://console.anthropic.com/settings/keys) 建立 API 金鑰，在「AI 設定」貼上即可。
- **API 是另外計費的**，依實際用量（tokens）付費，不包含在 Claude Pro 等訂閱方案裡。使用前需要在 Console 儲值或綁定付款方式，建議同時設定每月用量上限。
- 金鑰只存在這個瀏覽器的 localStorage，不會寫進 HTML 檔，把檔案傳給別人不會帶出去。但同一台電腦、同一個瀏覽器的其他使用者可以取得它，請只在自己的電腦上設定。可以隨時在「AI 設定」清除。

### 模型

| 模型 | 說明 |
| --- | --- |
| Claude Opus 5（預設） | 理解與排序最準確 |
| Claude Sonnet 5 | 較快、費用較低 |
| Claude Haiku 4.5 | 最快、費用最低，準確度較差 |

### 會傳送哪些資料

每次提問會把以下內容傳送到 Anthropic API：

- 全部已辨識公文的摘要：文別、收發方向、發文者、受文者、字號、日期、密等、主旨，以及說明、擬辦、附件的節錄。
- 你的問題、今天的日期，以及最近 5 輪對話的問題與 AI 當時的理解。

人工篩選與示範回覆不會傳送任何資料。

### 費用

以 50 份範例公文來說，每次提問送出的公文摘要約 1.7 萬字，使用 Claude Opus 5 大約每次幾美分到十美分左右（粗估，實際依回覆長度而定，可在 Anthropic Console 查看）。公文清單在同一段對話中不會變，接著追問時這部分會用 prompt caching 以較低的價格計費。

## 已知限制

- **欄位擷取規則是針對範例假資料調校的**，換成真實公文效果可能落差很大，詳見上面「這只是一個 PoC」。
- **AI 搜尋每次會送出全部公文的摘要**。幾百份以內還可行；公文更多時，需要先在本機挑出候選公文再交給 Claude 排序，目前還沒有實作。
- **API 金鑰直接在瀏覽器裡使用**，只適合個人測試。要給多人正式使用，應該改成由伺服器代為呼叫 API，不讓金鑰出現在瀏覽器。
- **示範回覆只是規則比對**，關鍵字與追問的彈性都有限，僅供體驗介面流程。
- 資料存在瀏覽器的 IndexedDB，綁定在「這台電腦＋這個瀏覽器」，不會跟著 `.html` 檔案移動；換瀏覽器或換電腦不會自動帶著走。
- 第一次使用需要網路（下載函式庫與 OCR 語言模型），第一次使用 Claude 時也會從 CDN 載入 Anthropic SDK；之後能否離線視瀏覽器快取而定，AI 搜尋則一定需要網路。

## 技術與致謝

- [PDF.js](https://mozilla.github.io/pdf.js/)（Mozilla）：PDF 渲染。
- [Tesseract.js](https://tesseract.projectnaptha.com/)：瀏覽器端 OCR 引擎（繁體中文＋英文語言模型）。
- [JSZip](https://stuk.github.io/jszip/)：批次匯出時在瀏覽器端打包 `.zip`。
- [Claude API](https://docs.anthropic.com/) 與 [Anthropic TypeScript SDK](https://github.com/anthropics/anthropic-sdk-typescript)：AI 搜尋，使用 structured outputs 讓回覆固定成畫面需要的格式。
- 視覺設計參考並改寫自 monday.com 的 [Vibe Design System](https://vibe.monday.com)（顏色、字級、間距、圓角等 design token，包含深色主題），純手刻 CSS 實作，並未使用 Vibe 的 React 元件庫或 npm 套件。
